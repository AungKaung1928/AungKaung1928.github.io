01

Microduck Balance and Push Recovery

  • Python
  • MuJoCo
  • PyTorch
  • ONNX
  • Balance-and-recover policy for a 25 cm, 14-servo open-source biped, trained with PPO in CPU MuJoCo, no GPU anywhere in the stack; the observation is only what the real robot's sensors report
  • Reward rebuilt from measurement, not taste: three of four penalties were under 0.25% of the return and were dropped or reweighted; the PD hold-pose baseline scores 175.2 ± 3.1 of 500 under the new reward
  • PPO after the first 25M of 50M steps: 332.6 ± 5.1 of 500 against the PD controller's 175.8 ± 0.2, trunk above the fall height 74% vs 47% of the time, 100 episodes × 5 seeds; no push knocked the learned policy over, so standing back up is still unmeasured; the return plateaued near 8M steps with the clip fraction at 0.7, and the loop ran at 3,300 env-steps/s, a quarter of the budgeted rate; the README says why
  • Domain randomisation measured on two held-out physics models, and it made the policy worse: the randomised policy never fell by the height test but was upright only 28% of steps against 47%, because it learned to brace in a crouch; it shrugged off backlash (+3.2 return against −15.2) and collapsed on rollers (147 against 374). Reported as it came out, and the height-only survival metric that hid it is fixed

Threaded C++ MuJoCo Backend, Bit-Identical

  • C++17
  • MuJoCo
  • pybind11
  • CMake
  • The same environment as project 01, rebuilt in C++17 because the Python one pays an inter-process round trip on every step: one model copy per environment, N environments on T threads of one process, and a drop-in vector env that the same PPO loop imports without a line changed
  • 6,275 of 6,275 observations bit-identical to the Python environment over 25 episodes, by reproducing numpy's pairwise sum, Python's libm pow and a float32 scale constant; tested on every commit under ASan, UBSan and TSan
  • 1.9–2.0× the Python vector env at 8 workers (12,327 vs 6,385 env-steps/s, alternated in the same run), and the comparison exposed that the Python budget had never counted its inter-process round trip

SO-ARM100 Manipulation with RL, Imitation and Language

  • Python
  • MuJoCo
  • PyTorch
  • LeRobot
  • One shared MuJoCo bench (four tasks, scripted IK expert, domain randomisation, six held-out physics settings, 100 episodes × 5 seeds) feeds three policy repos: curriculum PPO, imitation from BC through DAgger to ACT, and a language-conditioned multitask policy
  • Language generalisation is scored on held-out paraphrases and on task–colour pairs never seen together, with SmolVLA-base zero-shot in the same simulator as a reference line
  • Bench reference measured at 100 episodes × 5 seeds: the scripted expert reaches 0.93 on lift and pick_place but drops to 0.73 and 0.72 on the small cube, the one physics change that breaks it. The three policy repos are code complete and green in CI, but their tables are not yet measured, and the page says so

Tabletop Clutter Detector, INT8 on One Thread

  • Python
  • PyTorch
  • MuJoCo
  • ONNX Runtime
  • Anchor-free detector for 3–6 overlapping objects on a table; every box read straight out of the renderer's segmentation buffer, so no label is hand-drawn
  • mAP@[.5:.95] of 0.911 against a fitted classical pipeline's 0.532, with COCO mAP implemented from scratch and unit-tested rather than imported; 1.20 ms per image through ONNX Runtime on 8 threads
  • Step 6, INT8 and pruning: static INT8 with minmax calibration gives 1.38 ms on one thread (2.6× fp32, under the classical 2.13 ms) at mAP 0.910 vs 0.911; structured pruning was the wrong tool, half the channels cost 0.065 mAP for 2.42 ms, so INT8 alone is what would ship; one mAP-versus-latency curve at one thread holds every graph
