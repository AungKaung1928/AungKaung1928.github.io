Microduck Balance and Push Recovery

microduck-rl

A balance-and-recover policy for a 25 cm, 14-servo biped, trained with PPO in CPU MuJoCo. The page follows the project in order: a throughput figure that had to be corrected five times, a 48-dimensional observation built only from what the real sensors report, a reward rebuilt from measurement, a PD baseline to beat, and the full 50M steps, after a KL stop fixed a runaway step size in the second chunk. Domain randomisation was run and came out negative, and is reported as such; the ONNX export is measured.

全高25 cm・14サーボの二足ロボットに、バランス維持と転倒復帰のpolicyをPPOで学習させました（CPU版MuJoCo）。ページはプロジェクトの順に進みます。5回修正したスループットの数値、実機センサーが出す値だけで構成した48次元のobservation、計測に基づいて作り直したreward、超えるべきPD baseline、そして50M stepの本学習です。2つ目のchunkではKL stopで暴走したstep sizeを止めました。Domain randomisationは結果が悪化したため、そのまま報告しています。ONNX exportも計測済みです。

A C++ Environment That Matches Python to the Bit

mujoco-vecenv-cpp

The Microduck environment rewritten in C++17 and run on threads instead of processes. The claim is not speed first: 6,275 of 6,275 observations come out bit-identical to the Python reference, which took matching numpy's summation order, libm's pow and a float32 constant. Then the speed, measured with the two backends alternating in one run. Then the training run: three seeds per backend, no difference in return or survival.

Microduckの環境をC++17で書き直し、プロセスではなくスレッドで並列実行します。主張の第一は速度ではありません。6,275個のobservationすべてがPythonの参照実装とビット単位で一致します。そのためにnumpyの加算順序、libmのpow、float32の定数まで合わせました。次に速度で、2つのbackendを1回の実行内で交互に走らせて計測しています。最後に学習で、backendごとに3 seedsずつ学習し、returnにも生存率にも差は出ませんでした。

One Arm, Three Ways to Learn It

so-arm100-sim · -rl · -il · -vla

A shared MuJoCo bench for the SO-ARM100 arm (four tasks, a scripted IK expert, domain randomisation, held-out physics, one evaluation protocol) and three policy projects on top of it: curriculum PPO, imitation from behaviour cloning through DAgger to ACT, and a language-conditioned policy scored on held-out paraphrases. All of it is measured at 100 episodes × 5 seeds.

SO-ARM100アーム用の共通MuJoCoベンチ（4タスク、scripted IK expert、domain randomisation、held-out physics、統一された評価プロトコル）と、その上に載る3つのpolicyプロジェクトです。curriculum PPO、behaviour cloningからDAgger・ACTまでのimitation learning、そしてheld-outの言い換え文で評価するlanguage-conditioned policy。すべて100 episodes × 5 seedsで計測しています。

Tabletop Clutter Detector

mujoco-clutter-detect

An anchor-free detector finds objects on a table where they hide one another. COCO mAP is implemented from scratch rather than imported, an ablation compares photometric augmentation against randomising appearance at render time, and the model is then quantised to INT8 for a single CPU thread.

物体同士が重なり合うテーブル上で、anchor-freeの検出器が物体を見つけます。COCO mAPはライブラリを使わず自前で実装し、 photometric augmentationとレンダリング時の外観ランダム化をablationで比較しました。最後にCPU 1スレッド向けにINT8量子化しています。

PPO Against LQR

ppo-from-scratch

The same cart-pole solved twice: once with an optimal linear controller derived from the physics, once with PPO written out from first principles. Sixteen seeds, four ablations and a permutation test decide where the learned policy is genuinely better and where it is not.

同じcart-poleを2通りで解きます。1つは物理モデルから導いた最適線形制御（LQR）、もう1つはゼロから実装したPPOです。 16 seeds、4つのablation、permutation testで、学習したpolicyが本当に優れている点とそうでない点を判定しました。

Sub-Millimetre Cube Pose

mujoco-cube-pose-cnn

A small CNN recovers a cube's position and yaw angle from one rendered image. Two classical baselines come first — the second exposed a systematic radial bias in the first, fixed by a single scale factor — so the network's error is measured against something that already works.

小さなCNNが、レンダリング画像1枚から立方体の位置とyaw角を推定します。先に古典的なbaselineを2つ作りました。 2つ目のbaselineが1つ目の系統的な半径方向のbiasを見つけ、1つのscale係数で修正しています。そのため、ネットワークの誤差は「すでに動くもの」と比較して計測されています。

Panda Pick-and-Place Pipeline

moveit_pickplace_demo

A 7-axis Franka Panda clears seven balls off a table. Nothing is hard-coded: a simulated camera renders the scene, an OpenCV node finds the balls in the picture, a C++ node discards anything the arm cannot reach, and a state machine grasps only what survived that chain.

7軸のFranka Pandaがテーブル上の7個のボールを片付けます。座標のハードコードはありません。シミュレーション上のカメラが画像を描画し、 OpenCVノードが画像内のボールを検出し、C++ノードがアームの届かない対象を除外し、state machineはそこを通過したものだけを掴みます。

Watching a Robot Fleet

fleet_monitoring_ws

Three simulated robots publish where they are. A message bus carries it to two independent readers — one stores every reading, one notices when a robot has stopped and opens an alert a human can close. The whole fleet is described in one configuration file, and a job on every push brings the real container stack up and proves the chain end to end.

シミュレーション上の3台のロボットが自己位置をpublishします。メッセージバスがそれを2つの独立した受信側へ届けます。 1つはすべての値を保存し、もう1つはロボットの停止を検知して、人が閉じられるアラートを発行します。フリート全体は1つの設定ファイルで定義され、 pushのたびにCIが実際のコンテナ構成を立ち上げ、end-to-endで動作を検証します。
